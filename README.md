# ECO-GD II mobile — обновлённый интерфейс (Android Studio, Kotlin)

Это уже не просто набор XML-заготовок, а рабочий Android-проект: его можно
открыть в Android Studio как есть (`File → Open` → выбрать папку
`ECO-GD_II_mobile`) и запустить на эмуляторе/устройстве.

## Что изменено по запросу

### 1. Экран показаний — квадратный, с наложением данных на фото прибора
- Было: прямоугольная панель фиксированной высоты 200dp, с "плашкой" показаний
  под картинкой.
- Стало: `devicePanel` в `layout/activity_main.xml` — это кастомный
  `SquareConstraintLayout` (см. `ui/SquareConstraintLayout.kt`), который всегда
  квадратный (высота = ширине), независимо от размера экрана.
- Ваша фотография прибора лежит в `res/drawable-nodpi/device_eco_gd.png` и
  показывается через `ivDeviceImage` (`scaleType="fitCenter"`, изображение само
  квадратное 648×648, поэтому заполняет панель без обрезки).
- Показания (`tvGasValue`, `tvGasUnits`, `tvGasType`) выведены не отдельной
  плашкой, а прямо **поверх экранчика прибора на фото** — их положение задано
  через `Guideline` в процентах от панели (подобрано под реальные координаты
  LCD-дисплея на присланном фото) и центрировано зелёным моноширинным шрифтом,
  похожим на подсветку ЖКИ.
- Значения задаются программно в `MainActivity.kt` (`bindDemoReading()`) —
  на реальном устройстве туда подставляются данные, приходящие по Bluetooth.

### 2. Выбор устройства — всплывающий список с одним пунктом ECO-GD
- `spinnerDeviceType` в `activity_main.xml` теперь получает список из
  `res/values/strings.xml` → `<string-array name="device_types">` (сейчас там
  один пункт — `ECO-GD`).
- В `MainActivity.kt` (`setupDeviceTypeSpinner()`) список подключается через
  `ArrayAdapter` и сразу выставляется `setSelection(0)` — то есть при открытии
  приложения ECO-GD уже выбран, а при тапе на список показывается стандартный
  выпадающий попап Android с этим единственным пунктом.
- Когда появятся другие типы устройств — их достаточно дописать в
  `device_types` в `strings.xml`, код трогать не нужно.

### 3. Переключение вкладок — теперь реально работает
- `TabLayout` (Данные / Параметры / Эмуляция) в `activity_main.xml` больше не
  содержит статичных `TabItem` — заголовки и переключение полностью
  управляются кодом.
- `ui/MainPagerAdapter.kt` (`FragmentStateAdapter`) отдаёт в `ViewPager2` три
  фрагмента:
  - `ui/DataFragment.kt` — вкладка «Данные» (`fragment_data.xml`, список
    только для чтения);
  - `ui/ParametersFragment.kt` — вкладка «Параметры» (`fragment_parameters.xml`,
    редактируемые значения, изменённые подсвечиваются красным, кнопка
    «Запись» активируется только когда есть изменения);
  - `ui/EmulationFragment.kt` — вкладка «Эмуляция» (`fragment_emulation.xml`,
    общий переключатель + список функций эмуляции).
- `MainActivity.kt` (`setupTabs()`) связывает `TabLayout` и `ViewPager2` через
  `TabLayoutMediator` — переключение работает и тапом по вкладке, и свайпом по
  контенту.
- Списки внутри вкладок наполнены демонстрационными данными
  (`model/Parameter.kt`, `ui/ParameterAdapter.kt`, `ui/EmulationFunctionAdapter.kt`)
  — на реальном устройстве их нужно заменить значениями, приходящими по
  Bluetooth.

## Поиск устройств и приём показаний (BLE + Modbus RTU)

По вашему запросу протокол обмена был восстановлен реверс-инжинирингом
присланного `GasDetectorMobileV0_04.apk` — это Qt-приложение, и вся
бизнес-логика (включая Bluetooth и Modbus) скомпилирована в нативную
библиотеку `libGasDetectorMobile_*.so`, а не в Java/Kotlin-код. Из неё
извлечены:

**Транспорт (BLE UART):**
- Сервис: `49535343-fe7d-4ae5-8fa9-9fafd205e455`
- Характеристика (write без отклика + notify): `49535343-1e4d-4bd9-ba61-23c647249616`
- Это стандартный "прозрачный" BLE-UART мост (используется во многих
  BLE-модулях класса RN4870/HM-1x/JDY), поверх которого гонится Modbus RTU.

**Протокол данных (Modbus RTU):**
- Чтение регистров — функция `0x03`, кадр `[slaveId][0x03][startHi][startLo][countHi][countLo][crcLo][crcHi]`
- CRC16 — стандартный Modbus (полином `0xA001`)
- Реализация: `ble/ModbusRtu.kt`

**Известные адреса регистровых блоков** (найдены в `DataParse()` эталонного
устройства "Optimus" внутри той же библиотеки — единственного устройства,
код которого реально присутствует в присланном APK):
- `158` (0x9E) — блок "Данные": статус + загазованность (float)
- `244` (0xF4) — блок "Параметры": ModbusID, Baudrate, пороги 1/2
- `260` (0x104) — блок "Эмуляция": упакованные флаги LED/реле

⚠️ **Важная оговорка.** В присланном APK реализовано только устройство
`QOptimusMobile` ("Оптимус") — класса `ECO-GD` в этом билде нет вообще.
BLE-транспорт (UUID сервиса/характеристики) и формат кадров Modbus, скорее
всего, общие для всей линейки ЭКОХИМПРИБОР, поэтому реализация должна
подключаться и опрашивать реальный ECO-GD. А вот точная раскладка регистров
внутри блока 158 (что именно лежит в каждой паре регистров — газ,
температура, ток и т.д.) подтверждена только для Optimus и **должна быть
перепроверена на реальном ECO-GD** — либо логированием сырых байт ответа
(экран "Логи" в приложении), либо у производителя. Сейчас на экран
выводится значение из регистров 168–169 как загазованность (наиболее
вероятная позиция по структуре Optimus).

**Реализация:**
- `ble/BleUartConstants.kt` — UUID-ы сервиса/характеристики/CCCD
- `ble/ModbusRtu.kt` — CRC16, сборка запросов, разбор ответов (со склейкой
  многокадровых BLE-нотификаций)
- `ble/BleModbusManager.kt` — сканирование, GATT-подключение, включение
  notify, циклический опрос (раз в секунду) блока "Данные"
- `MainActivity.kt` — кнопки "Поиск"/"Стоп" запускают/останавливают
  сканирование (с запросом рантайм-разрешений `BLUETOOTH_SCAN` /
  `BLUETOOTH_CONNECT` на Android 12+, `ACCESS_FINE_LOCATION` на более
  старых), список найденных устройств уходит в `spinnerFoundDevices`,
  "Подключиться" вызывает `BleModbusManager.connect()`, после успешного
  подключения начинается циклический опрос и обновление показаний на
  фото прибора.
- Чекбокс "Все устройства": без галочки список фильтруется по имени
  (устройства, содержащие "eco"/"optimus"/"gd" в названии), с галочкой —
  показываются все найденные BLE-устройства рядом.
